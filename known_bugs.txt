Crashes (RESOLVED in v1.1.0-beta5 — see STAGE1_GAMETHREAD_NOTE.md / CRASH_HANDOFF.md):

- [FIXED in 1.1.0-beta5] The recurring access-violation crash (the long-standing one). Root cause:
  warding mutated live render/collision state from UE4SS LoopAsync callbacks (a SEPARATE async thread,
  NOT the game thread), racing the engine's render/cluster-tree workers. Fix: layer-3 book-pile writes
  moved to the game thread (ExecuteInGameThread, BOOK_VIS_GAMETHREAD) + a world-epoch teardown guard.
  Confirmed by a full 1-4h crash-free playthrough. Layers 1 & 2 remain off-thread (rarer race; the
  game-thread "pump" is the planned follow-up to bring them on without UE4SS #1180).

- [FIXED in 1.1.0-beta5] 12AF29C8 / 7567C016 — EXCEPTION_ACCESS_VIOLATION reading 0x1e3010030 /
  0x300000037 (use-after-free read), going to the TITLE / MAIN MENU (title->M01 LoadMap / world
  reload). First seen 2026-06-02 21:11 (beta4+Stage1), then REPRODUCED going to the main menu at 22:01.
  Cause: a deferred book-pile-hiding pass (apply_book_visibility, marshaled to the game thread) ran on
  the FREED old-world HISM array during the reload — a native AV that Lua pcall can't catch.
  Fix: a world-epoch counter (reset_hism_state bumps it; the game-thread closure bails if it changed
  between scheduling and running). Confirmed catching the race live (b2-stale-world marker, no crash).
  Artifacts: "crash reports/title-reload 2026-06-02 2111..." and ".../mainmenu-AV 2026-06-02 2201...".

Book visibility edge cases (rare ~3/3072 over a 1-4h run; ADDRESSED in v1.1.0-beta6, field-validation pending):

- "Visible but not grabbable" — a warded book briefly shown by the game's view-dependent toggle. beta6:
  a SetActorVisible PRE-hook keeps warded books hidden at show-time (BOOK_EVENT_ENFORCE).
- "Vanishes when looked at / picked up, fine after dropping" — an unwarded book stuck hidden. beta6:
  a SetActorVisible POST-hook re-shows it (BOOK_EVENT_REVEAL).
  These are the two directions of the same actor-vs-pile desync. Confirm via the [book-hook]
  ENFORCE/REVEAL log counts over a full playthrough + tester reports. If REVEAL stays 0 but vanishing
  books persist, symptom 2 isn't the stale-hide we targeted — look elsewhere. See WARDING_SYNC_PLAN.md.

1.1.0 Known Issues:

- "Visible in the pile, invisible when held" (hidden mode only). A received (unwarded) book occasionally
  renders invisible while held or looked at, though it's visible in the shelf pile and still grabbable.
  Rare and RANDOM — different books each session, sometimes 1 book, sometimes a few, sometimes a whole
  series. WORKAROUND: return to the title screen and Continue, or relaunch — it's per-session only and the
  affected books come back normal (nothing is lost; the save is never corrupted).

  Confirmed: hidden mode only (stacks never hides books, so it never exercises the machinery); runtime-only,
  self-heals on world reload (book actors re-spawn); it's the actor's SM_Book_1 mesh that's affected, not the
  pile/HISM. A captured grab read 100% HEALTHY on every field (bHidden=false, mesh shown, scale 1.0, opacity
  nil, transform/CPD normal, tints in range), and it SURVIVES RefreshInfo (called 3,467x in one session) — so
  it's below the appearance layer. Leading hypothesis: a stale/detached render proxy on the held actor (it's
  "visible" by every flag but not actually drawn), cleared only by the full actor re-spawn a reload does.

  Ruled out: opacity, WPO / CustomPrimitiveData displacement (UpdateWPO is dead code; cpd empty), transform /
  mesh-Z, scale, the bHidden / mesh-visibility flags, null mesh, tint corruption, BookInfo (RefreshInfo).

  Mitigation shipped: BOOK_ACTOR_RECONCILE heals the flag-based variants (NOT this render-proxy one).
  CAPTURE for the open variant ships via the GRAB-PATH (BOOK_EVENT_HOOKS, on by default) — pick up an
  affected book and the log records its full state. Grep UE4SS.log for:
    [book-hook] *** BROKEN-GRAB ***          a grabbed book that looks broken (full state dump follows)
    [book-hook] *** INVISIBLE-CONFIRMED ***  a held book confirmed genuinely not-drawn (~0.6s after grab)
  A passive auto-scanner (BOOK_INVIS_SCAN) also exists but SHIPS OFF: on this build the game keeps nearly
  all book actors bHidden=false, so "shown but not drawn" is dominated by normal off-screen frustum culling
  (~365/sweep -> ~27 false suspects in 2 min) and it floods the log. It needs a camera-FOV filter to be
  usable. Toggle either via Scripts/diag_flags.lua (changes no gameplay).

  Next fix step (from a captured dump): renderInMainPass=false -> re-assert it in the reconcile; everything
  reads visible but WasRecentlyRendered=false -> force a component re-register on the held actor (the
  lightweight equivalent of the re-spawn that already heals it). Crash-stabilized rendering code, so gate + A/B.

  (Supersedes the beta6 "Book visibility edge cases" note above: symptom 1 "visible but not grabbable" is now
  handled by ENFORCE + the reconcile; symptom 2's render-proxy form is the open issue here.)

- Intermittent native crash / freeze from the warding-vs-engine render race (hidden mode). Two shapes seen:
    * During play: a routine 5s warding pass (esp. the OFF-thread Layer-2 bookcase ward) races the engine's
      parallel render reads -> a native access violation the mod can't catch. Decoupled (the crash_trace tail
      is heartbeats, no mod write in flight). Rare; previously ~3/3072 books over a 1-4h run.
    * Return-to-menu: a heavy ward pass right before the world reload leaves book/bookcase/HISM components
      mutated, and the engine's teardown of them hangs (multi-minute freeze) then crashes.
  Long-standing (see CRASH_HANDOFF.md). 1.1.0 mitigates Layer 3 (game-thread + world-epoch teardown guard) but
  Layers 1-2 still run off-thread and the menu-teardown window isn't fully guarded, so both shapes can still
  occur. Planned real fix (post-1.1.0): a game-thread "pump" moving Layers 1-2 on-thread without the UE4SS
  #1180 burst, plus un-warding before teardown.

  REPORTING (on the 1.1.0 build, please): if you crash or freeze, send the crash-report folder, especially:
    - Mods/Librarian-AP/crash_trace.log   (breadcrumb ledger -- the TAIL names the last mod op before death)
    - .../Win64/UE4SS.log                  (last 100-200 lines)
    - one line on what you were doing (placing a row, returning to menu, walking a shelf, ...)
  Confirm the trace header says mod=1.1.0-rc1 (older builds don't help). Optional A/B: set CASE_WARDING=false
  or BOOK_VISIBILITY=false in Scripts/diag_flags.lua and report whether the crash stops.
